LangChain 1.x Capstone – Student Implementation Guide

Build incrementally — understand why, follow detailed steps, run and test before continuing

How this guide works
  • Read langchain_project_specification.html first for requirements.
  • Each step has: Why (the reason), What to do (detailed actions), and Run & observe (commands + what you should see).
  • Do not paste entire files. Build one small piece, save, run the check, then continue.
  • When Streamlit is running, stop with Ctrl+C, restart after edits: python -m uv run streamlit run app.py
  • Optional syntax check anytime: python -m py_compile app.py

1 Initialize the project with uv

Why: You need an isolated Python environment and a standard project layout before adding Streamlit or LangChain. uv creates pyproject.toml and a virtual environment so dependencies stay reproducible.

1.1 — Install uv

What to do: Open a terminal and install uv with the official installer. Do not use pip. After it finishes, close the terminal and open a new one so uv is on your PATH.

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
Run & observe
uv --version

You should see a version string (e.g. uv 0.x.x). If the command fails, reopen the terminal and try again before continuing.

1.2 — Create the project folder

What to do: Choose a parent folder (e.g. C:\projects). Run uv init langchain-bot. Change directory into langchain-bot.

Run & observe
dir

On Windows you should see at least pyproject.toml, main.py, and README.md.

Step 1 complete — checkpoint
uv run python --version

✅ Python runs inside the uv-managed environment. Proceed to Step 2.

2 Add dependencies & .env

Why: The capstone uses Streamlit (UI), LangChain 1.x (agent), Chroma (RAG), SQLite checkpointer, SQL toolkit, and Gmail. Installing everything now avoids mid-project import errors.

2.1 — Add packages

What to do: From the project root, run one uv add command with all packages:

python -m uv add streamlit langchain langchain-openai openai python-dotenv langgraph langgraph-checkpoint-sqlite langchain-community chromadb langchain-text-splitters google-auth-oauthlib google-auth-httplib2 google-api-python-client
Run & observe
python -m uv run python -c "import streamlit, langchain; print('OK')"

Should print OK. If any import fails, re-run the uv add line.

2.2 — Create .env

What to do: In the project root, create a file named .env (same folder as pyproject.toml). Add your OpenAI key:

OPENAI_API_KEY=sk-your-key-here
CHECKPOINTS_DB_PATH=checkpoints.sqlite

Why CHECKPOINTS_DB_PATH: Later steps store LangGraph conversation state in a SQLite file; this env var lets you change the path without editing code.

2.3 — Protect secrets

What to do: Create or edit .gitignore. Add lines for .env, credentials.json, token.pickle, *.db, chroma_db/, chat_threads.json if you plan to use git.

Step 2 complete — checkpoint
python -m uv run python -c "from dotenv import load_dotenv; import os; load_dotenv(); print('key set' if os.getenv('OPENAI_API_KEY') else 'MISSING')"

✅ Should print key set. ❌ If MISSING, check .env filename and location.

3 Streamlit UI scaffold

Why: Before agents and tools, you need a working chat shell: display history, accept input, call the model. This proves OpenAI + Streamlit + dotenv work together.

File: Create empty app.py in the project root. Add the pieces below in order. Save after each sub-step.

3.1 — Imports

What to do: At the top of app.py, import:

  • streamlit as st
  • load_dotenv from dotenv
  • ChatOpenAI from langchain_openai
  • AIMessage, HumanMessage from langchain_core.messages
Run & observe
python -m py_compile app.py

No output = syntax OK.

3.2 — get_llm()

Why: Centralizes model name and temperature so you change them in one place later.

What to do: Add a function that returns ChatOpenAI(model="gpt-4.1-mini", temperature=0.3) (or similar mini model your course uses).

3.3 — init_session()

Why: Streamlit reruns the whole script on every click. st.session_state keeps chat history across reruns.

What to do: If "messages" is not in session state, set it to a list containing one AIMessage with a short greeting (e.g. "Hi! Ask me anything.").

3.4 — render_history()

Why: Converts stored LangChain messages into visible chat bubbles.

What to do: Loop over st.session_state.messages. For each message, decide role: "user" if it is a HumanMessage, else "assistant". Use st.chat_message(role) and st.markdown(msg.content).

3.5 — chat_round(llm, user_input)

Why: One turn = append user text, call model with full history, append assistant reply.

What to do:

  1. Append HumanMessage(content=user_input) to messages.
  2. Call response = llm.invoke(st.session_state.messages).
  3. Append response to messages.

3.6 — main()

Why: Wires the Streamlit page: config, dotenv, session, history, input, one LLM round, rerun.

What to do:

  1. st.set_page_config(page_title="LangChain Bot", page_icon="🤖")
  2. load_dotenv()
  3. Call init_session() then render_history()
  4. prompt = st.chat_input("Ask a question")
  5. If prompt is truthy: get LLM, show spinner inside st.chat_message("assistant"), call chat_round(llm, prompt), then st.rerun()

3.7 — Entry point

What to do: At the bottom: if __name__ == "__main__": main()

Step 3 complete — checkpoint
python -m uv run streamlit run app.py
  1. Browser opens at http://localhost:8501
  2. You see the greeting message
  3. Type Hello — assistant responds (uses your API key)

❌ API errors → check .env. ✅ Proceed to Step 4.

4 Chat prompt template & chain

Why: Raw llm.invoke(messages) has no system instruction slot. A ChatPromptTemplate + LCEL chain (prompt | llm) lets you add a fixed system message and a MessagesPlaceholder for history — the pattern agents use later.

Keep unchanged from Step 3: get_llm, init_session, render_history, entry point.

4.1 — Imports

What to do: Add ChatPromptTemplate and MessagesPlaceholder from langchain_core.prompts.

4.2 — build_chain(llm) (new function)

What to do: Insert after get_llm(), before init_session().

  1. Build a template with three parts in order:
    • System: e.g. "You are a concise, helpful assistant. Use prior chat history to stay on context."
    • MessagesPlaceholder(variable_name="history")
    • Human template with placeholder {input}
  2. Return prompt | llm (LCEL chain).

4.3 — Replace chat_round()

What to do:

  1. Still append the user HumanMessage first.
  2. Build chain with build_chain(llm).
  3. Invoke with a dict: {"input": user_input, "history": st.session_state.messages}.
  4. Append the returned AIMessage to messages.

4.4 — Update main()

What to do: Immediately after set_page_config, add st.title("LangChain Bot") and a short st.caption(...) so the page is clearly labeled.

Step 4 complete — checkpoint

Restart Streamlit. Then in the browser:

  1. Ask: "What is Python?"
  2. Ask: "Tell me more about it"
  3. Bot should continue the topic (context preserved via MessagesPlaceholder)

❌ If context is lost, check that history in chain.invoke includes prior messages.

6 Login & conversation_id

Why: The specification requires login by email. Each chat thread needs a UUID conversation_id so later the checkpointer and tickets can reference the correct conversation. Build the UI in small slices and test after each slice.

Do not store chat transcripts in SQL.

The spec keeps business data in ecommerce.db and conversation state in the LangChain checkpointer. Session state is enough for this step. In Step 11 you will load history with agent.get_state(config) — the same pattern as 03-02streamlit-chatbot-memory.html.

8 RAG policy search tool

Why: The agent needs a tool that retrieves relevant policy chunks from ChromaDB. Building the index once and reusing it on disk keeps startup fast.

File: Create src/langchain_bot/rag_tool.py in order §8.1 → §8.6.

8.1 — Imports + module cache

What to do: Import Path, LangChain @tool, TextLoader, Chroma, Document, OpenAIEmbeddings, RecursiveCharacterTextSplitter. Add module variable _vector_store = None (singleton cache).

8.2 — load_policy_documents()

What to do: Resolve policies/ at project root (parent.parent.parent from this file). Glob *.txt. For each file, TextLoader load, set metadata["source"] to filename, extend a documents list. Return all documents.

Run & observe
python -m uv run python -c "from langchain_bot.rag_tool import load_policy_documents; print(len(load_policy_documents()))"

Count should be ≥ 3 (one doc per file minimum).

8.3 — split_documents(documents)

Why: Whole files are too large for precise retrieval; chunks match user questions better.

What to do: RecursiveCharacterTextSplitter with chunk_size ~800, overlap ~150. Return split documents.

8.4 — get_vector_store()

What to do:

  1. If _vector_store already set, return it (global assignment when creating).
  2. Persist dir = project root / chroma_db.
  3. Embeddings = OpenAIEmbeddings (e.g. text-embedding-3-small).
  4. If chroma_db exists and non-empty → open existing Chroma.
  5. Else → load policies, split, Chroma.from_documents, persist, cache instance.
  6. Print short status lines so you see "Loading" vs "Loaded existing".
Run & observe
python -m uv run python -c "from langchain_bot.rag_tool import get_vector_store; get_vector_store(); print('done')"

First run: may take ~1 min, creates chroma_db/. Second run: should say loaded existing.

8.5 — @tool search_policies(query: str)

What to do: Docstring must say: for policy/FAQ only, not user orders. Call get_vector_store(), similarity_search with top k (e.g. 4), format chunks with source labels into one string return value.

11 Checkpointer & agent.get_state

Why: The spec stores conversation history in a LangChain checkpointer, not in SQL. SqliteSaver keeps agent state per thread_id. The UI should not keep its own copy of transcripts. After each turn (and when switching chats), redraw from agent.get_state(config) — the same pattern as 03-02streamlit-chatbot-memory.html.

11.1 — Update agent.py

What to do:

  1. Import SqliteSaver, os, sqlite3.
  2. get_checkpointer(): singleton; path from CHECKPOINTS_DB_PATH env or checkpoints.sqlite; connect with check_same_thread=False (Streamlit multi-thread); SqliteSaver(conn=...); call setup().
  3. Pass checkpointer=get_checkpointer() into create_agent.
  4. get_thread_config(user_email, conversation_id) returns dict with configurable: {thread_id: f"{email}:{conv_id}"} and recursion_limit: 20.

11.2 — Sidebar: conversation IDs only (not messages)

Why: The checkpointer already has the messages. The UI only needs a list of thread ids so the dropdown can switch chats — like chat_threads.json in the memory chatbot lab.

What to do:

  1. Add helpers (JSON file is fine): load_threads(user_email), save_threads, add_thread(user_email, conversation_id).
  2. Store [{"id": "...", "label": "Chat abc12345"}, ...] per user. Do not store message bodies.
  3. On login: load that user's thread ids. If any exist, set conversation_id to the first. Else start a new UUID and add_thread.
  4. "Start new conversation": new UUID, add_thread, set conversation_id, st.rerun().
  5. Selectbox: when the user picks another id, set conversation_id and rerun. Do not copy messages from a dict — get_state will load that thread.

11.3 — Replace render_history() with get_state

What to do: Stop rendering st.session_state.messages. For the active user + conversation:

config = get_thread_config(user_email, conversation_id)
snapshot = get_agent().get_state(config)
for msg in snapshot.values.get("messages", []):
    if msg.type == "human":
        with st.chat_message("user"):
            st.markdown(msg.content)
    elif msg.type == "ai" and msg.content:
        with st.chat_message("assistant"):
            st.markdown(msg.content)

Skip empty AI messages (tool-call-only turns). Human and AI bubbles come from the checkpointer, not from session state.

11.4 — Replace chat_round()

What to do:

  1. Import get_thread_config.
  2. Invoke the agent with only the new user message and the thread config: get_agent().invoke({"messages": [{"role": "user", "content": user_input}]}, config=get_thread_config(...))
  3. Call st.rerun(). The next run of render_history() reads the full thread from get_state.

Do not append messages to session as the source of truth. Do not write transcripts to SQLite or JSON.

15 Human-in-the-loop & Admin dashboard

Why: The spec forbids auto-approving returns/cancellations. HITL interrupts dangerous tools until an admin resumes the same LangGraph thread.

End-to-end flow (read before coding)

  1. Customer asks cancel/return → agent verifies via SQL → optional email → calls action tool → interrupt.
  2. handle_interrupt writes pending_actions row; customer sees pending message.
  3. Admin on port 8502 approves → resume_with_decision(thread_id, ...) → tool runs SQL updates → confirmation email.

15.1 — context.py

What to do: Dataclass SessionContext with user_email, conversation_id, role (default customer). Used as context_schema on create_agent so tools get identity via ToolRuntime — LLM only passes order_id etc.

15.2 — Extend ecommerce_setup.sql

What to do: Add pending_actions table (thread_id, user_email, action_type, order_id, product_name, reason, status, timestamps). Re-run db_init.

Run & observe
python -m uv run python -c "import sqlite3; print(sqlite3.connect('ecommerce.db').execute(\"SELECT name FROM sqlite_master WHERE type='table' AND name='pending_actions'\").fetchone())"
